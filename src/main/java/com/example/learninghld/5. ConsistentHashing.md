## Consistent Hashing

Consistent Hashing is a distributed hashing scheme that operates independently of the number of servers or objects in a distributed hash table by assigning them a position on an abstract circle, or hash ring. This allows servers and objects to scale without affecting the overall system.

So main purpose is to distribute the load among the servers equally and during addition or deletion of server, minimum number of keys to be rebalanced.

### Problem Consistent Hashing Solves

In traditional hash-based distribution systems:
- Data is distributed using `key % n` where n is the number of servers
- When n changes (server added/removed), almost all keys need to be remapped
- This causes massive data migration, overwhelming the system during scaling events

### How Consistent Hashing Works

1. **Hash Ring Creation**:
   - Create a circular hash space (typically 0 to 2^32-1)
   - Hash each server to a position on this ring using a hash function

2. **Data Placement**:
   - Hash each data item to a position on the ring
   - Assign the data to the first server encountered when moving clockwise from the data's position

3. **Server Addition/Removal**:
   - When a server is added, it only takes some load from its neighbor
   - When a server is removed, its load is distributed only to its neighbor
   - In both cases, most data mappings remain unchanged

4. **Virtual Nodes**:
   - To improve distribution, each physical server is represented by multiple virtual nodes
   - Each server is mapped to multiple points on the ring
   - Helps achieve better balance, especially with heterogeneous servers

### Visual Explanation

Imagine a circle (the hash ring) with positions 0 to 359 (like degrees):
- Server A hashes to position 50
- Server B hashes to position 150
- Server C hashes to position 250
- Data item X hashes to position 100 → assigned to Server B
- Data item Y hashes to position 200 → assigned to Server C
- Data item Z hashes to position 300 → assigned to Server A

If Server B fails:
- Only data items between positions 150 and 250 need to move to Server C
- All other data assignments remain unchanged

### Advantages

- **Minimal Redistribution**: When servers are added/removed, only a small fraction of keys need to be remapped
- **Scalability**: Servers can join and leave with minimal disruption
- **Balance**: With virtual nodes, load is distributed more evenly
- **Heterogeneity**: Can account for different server capacities by assigning more virtual nodes to more powerful servers

### Use Cases

- **Distributed Caches**: Memcached, Redis Cluster
- **Distributed Databases**: Cassandra, DynamoDB
- **Content Delivery Networks**: Akamai, Cloudflare
- **Load Balancers**: Distributing requests across backend servers

### Implementation Considerations

- **Hash Function Selection**: Should provide uniform distribution (e.g., MD5, SHA-1)
- **Virtual Node Count**: More virtual nodes improve balance but increase memory usage
- **Replication**: Often combined with replication for fault tolerance

### Code Example (Simplified Pseudocode)

```
function addServer(server):
    for i from 1 to NUM_VIRTUAL_NODES:
        virtualNode = server + "-" + i
        position = hash(virtualNode)
        ring[position] = server

function removeServer(server):
    for i from 1 to NUM_VIRTUAL_NODES:
        virtualNode = server + "-" + i
        position = hash(virtualNode)
        remove ring[position]
```
